# CUConnect — Engineering & Design Decisions

This log records every design choice made where requirements left room for judgement, along with a concise rationale.

1. **No report template file present in workspace**: Followed the exact section outline specified in the project instructions (title page through conclusion with GitHub URL, capped at 15 pages and <= 5 short code snippets).
2. **All 6 enhancements implemented, image posts skipped**: Implemented Notifications (`Queue`), Likes (`HashTable`) + Threaded Comments (tree + pre-order DFS), Trending Posts (`MinHeap`), Undo + Console Back-Navigation (`Stack`), Communities (iterative DFS with `Stack`), and Alphabetical Browse All Students (`AVLTree` with LL/RR/LR/RL rotations); skipped image posts as instructed.
3. **Pure stdlib core with zero `collections`/`heapq`/`sorted` in `core/`**: Even helper sorting and tie-breaking use our hand-written `merge_sort`, `binary_search`, `HashTable`, `Queue`, `Stack`, and `MinHeap` so students can defend 100% of core code in viva.
4. **Polynomial rolling hash parameters (`base = 31`, `mod = 1_000_000_007`)**: Small prime base and standard 32-bit-safe prime modulus make hash calculations easy to trace by hand on a whiteboard during viva.
5. **HashTable resize policy (initial capacity 16, double when load factor > 0.75)**: Standard textbook load-factor threshold balancing lookup speed $O(1)$ average and memory overhead.
6. **Deterministic tie-breaking with injectable clock and sequence counter**: `CUConnectService` accepts an injectable `clock` function and maintains a monotonic `_seq` counter so feed ordering, notifications, and tests never suffer from wall-clock flakiness.
7. **Home feed shows connections' posts only by default (`include_self=False`)**: Matches the problem statement ("A home feed of posts from your connections, newest first"); own posts are displayed on the Post Composer and Profile pages.
8. **People You May Know excludes self, direct connections, and users with a pending request**: BFS to depth 2 naturally finds non-connected 2nd-degree candidates; excluding already-pending requests prevents suggesting someone the user has already requested (configurable via `exclude_pending=True`).
9. **Degree display labels**: Distance `0` -> `"Self"`, `1` -> `"1st"`, `2` -> `"2nd"`, `3` -> `"3rd"`, `>= 4` -> `"3+"`, unreachable -> `"Not connected"`; shortest chain is returned for all reachable pairs (including 4+ hops).
10. **Trending posts recency window**: Defaults to the last 7 days (`7 * 86400` seconds relative to the injectable clock) and scores posts as `likes + 2 * total_comments` (counting replies), considering posts from the user's connections.
11. **Undo semantics**: Per-user `Stack` records `send_request` and `remove_connection` actions in memory during a session; undoing validates that the action is still reversible (e.g., request still pending, or users still disconnected) and writes through to SQLite.
12. **SQLite storage-only hydration**: `storage/repository.py` performs only simple table CRUD (`SELECT *`, `INSERT`, `UPDATE`, `DELETE` — no `JOIN`, `ORDER BY`, `GROUP BY`, or aggregates); startup ordering by `seq_id` is performed in Python using our own `merge_sort`.
13. **Seed graph topology (18 students across 3 connected components)**: Component 1 (10 students, containing an 8-student core dry-run subgraph with distances 1, 2, 3, and 4/`3+`), Component 2 (5 VLSI/Robotics students), and Component 3 (3 first-year students) so Connected Components visibly demonstrates multiple communities while supporting rich intra-community paths and suggestions.
14. **Username normalization**: Usernames are stored and matched in lowercase (stripped of whitespace, 3–30 alphanumeric/underscore chars) to avoid confusing near-duplicate accounts like `Aarav` vs `aarav`.
15. **Password security**: Uses `hashlib.pbkdf2_hmac("sha256", ..., 100_000)` with a 16-byte random salt per user, verified via `hmac.compare_digest`; login always raises the generic message `"Invalid username or password."` so username existence is never leaked.
